# 테크 시그널 — 검수 파이프라인

> 시제품과 양산 사이를 아는 사람이 읽는 AI 하드웨어

AI가 매일 아침 기사를 모으고 **원문에서 확인되는 것만** 정리해 두면, 운영자는 하루 10분 동안 상위 3건에 현장 한 줄 코멘트를 남깁니다. 그 코멘트가 다음 날 AI 프롬프트의 예시로 다시 들어가서, 시간이 갈수록 AI의 선별 기준이 운영자를 닮아갑니다.

```
06:30 GitHub Actions
  수집(RSS) → 1차 선별(점수) → 구조화 → 근거 검증 → data/latest.json
                    ▲                                     │
                    │ few-shot 예시                        ▼
            data/comments.json  ◀──── 저장 ──── admin.html (폰에서 10분)
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `pipeline.py` | 수집·선별·구조화·검증. 프롬프트 두 개(`SCORE_PROMPT`, `STRUCT_PROMPT`)가 이 안에 있음 |
| `index.html` | **공개 페이지.** 내가 판단을 남긴 기사만 보여줌 (시그널 / 실패 사례 / 예측 성적표 / 소개) |
| `admin.html` | 검수 화면 (나만 씀). 단일 HTML + Tailwind + 바닐라 JS |
| `data/meta.json` | 렌즈 정의·카테고리. 파이프라인이 매번 써 주고, 공개 페이지가 읽음 |
| `.github/workflows/daily.yml` | 매일 06:30(KST) 자동 실행 |
| `data/latest.json` | 오늘 기사 (자동 생성) |
| `data/archive/YYYY-MM-DD.json` | 날짜별 보관 (자동 생성) |
| `data/comments.json` | 운영자 코멘트·예측·실패 DB (검수 화면이 저장) |
| `data/programs.json` | 지원사업 목록 (직접 관리) |
| `data/seen.json` | 이미 처리한 기사 id (자동 생성) |

## 왜 프론트에서 LLM을 직접 부르지 않나

브라우저에서 LLM API를 호출하면 API 키가 페이지 소스에 그대로 노출됩니다. 깃허브에 공개하는 순간 누구나 그 키로 요금을 쓸 수 있어요. 그래서 구조를 이렇게 나눴습니다.

- **LLM 호출**은 GitHub Actions에서만 한다. 키는 저장소 Secrets에 들어가고 코드에는 없다.
- **화면**은 만들어진 JSON만 읽는다.
- **코멘트 저장**은 GitHub API로 한다. 토큰은 내 폰 브라우저에만 저장되고, 저장소 하나·Contents 권한만 가진 토큰을 쓴다.

## 설치 (한 번만)

1. 이 폴더를 깃허브 저장소로 올립니다.
2. **API 키 등록**: 저장소 → Settings → Secrets and variables → Actions
   - Secrets에 `LLM_API_KEY` 추가
   - Variables에 `LLM_PROVIDER` = `gemini` (Claude를 쓰면 `anthropic`, 비워두면 Claude로 동작)
   - `LLM_MODEL`은 비워두면 기본 모델을 씁니다: Gemini는 `gemini-3.5-flash-lite`, Claude는 `claude-haiku-5-5`. 모델이 단종되면 이 값만 바꾸면 됩니다.
   - 무료 사용량은 분당 요청 수가 제한돼 있어서, 파이프라인이 "너무 많다"는 응답을 받으면 기다렸다 다시 보냅니다. 그래서 첫 실행이 몇 분 걸릴 수 있어요.
   - Gemini 무료 사용량으로 보낸 내용은 구글이 서비스 개선에 쓸 수 있습니다. 여기서 보내는 건 공개 뉴스 제목·요약과 이미 공개할 코멘트뿐이라 문제는 없지만, 알고는 계세요.
3. **GitHub Pages 켜기**: Settings → Pages → Branch를 `main` / root로 지정. 그러면 공개 페이지는 `https://<사용자명>.github.io/<저장소>/`, 검수 화면은 같은 주소 뒤에 `admin.html`로 열립니다.
4. **검수용 토큰 만들기**: GitHub → Settings → Developer settings → Fine-grained tokens
   - Repository access: 이 저장소만
   - Permissions: Contents → Read and write (다른 권한은 주지 않기)
   - 만든 토큰을 admin.html의 **설정** 탭에 넣습니다.
5. Actions 탭에서 `daily-signal`을 **Run workflow**로 한 번 수동 실행해 보세요.

## 내 컴퓨터에서 먼저 보기

```bash
pip install -r requirements.txt
python pipeline.py --sample      # 네트워크 없이 샘플 데이터 생성
python -m http.server            # 그 뒤 브라우저에서 localhost:8000/admin.html
```

실제 실행은 `LLM_API_KEY=... python pipeline.py`.

## 하루 10분 검수 흐름

1. 아침에 admin.html을 엽니다. 상위 3건이 **필수**, 나머지는 접혀 있습니다.
2. 각 카드에서 **원문 확인 항목**만 봅니다. 원문 구절이 실제로 있는 값만 남아 있고, 탭하면 근거 구절이 보입니다.
3. **내가 보는 관점**을 최대 3개 고릅니다. 맞는 게 없으면 "해당 없음".
4. 코멘트 칸에 한 줄. 막히면 회색 질문을 참고하세요. (질문은 답을 정해주지 않는 형태로만 나옵니다)
5. 필요하면 버튼으로 추가
   - ⭐ **학습 예시로**: 잘 쓴 코멘트. 다음 날부터 프롬프트에 우선 들어갑니다.
   - 🔮 **예측 남기기**: 3·6·12개월 뒤 **예측 복기** 탭에 다시 뜨고, 적중률이 쌓입니다.
   - 🧱 **실패 DB**: 하드웨어 실패 사례로 저장. 원인 태그를 쉼표로.
6. 아래 **저장**. 작성 중인 내용은 브라우저에 자동 보관되니 중간에 닫아도 됩니다.
7. 저장하면 그때 **AI가 고른 렌즈와 AI 추정(양산 난이도·예상 병목)이 공개**되고, 내 렌즈와의 일치율이 표시됩니다. 저장된 기사는 다시 고칠 수 없습니다. AI 답을 보고 내 판단을 바꾸면 데이터가 오염되기 때문입니다.

## 공개 페이지 (`index.html`)

- **판단을 남긴 기사만** 올라갑니다. 건너뛴 기사, 코멘트가 빈 기사, AI가 정리만 한 기사는 나가지 않습니다.
- 카드 순서: 내 한 줄 → 내 관점 → 기사 제목(원문 링크) → AI 요약(따로 표시) → 원문 확인 항목 → 예측.
- 원문 본문이나 원문 문장은 싣지 않습니다. 요약은 AI가 자기 말로 다시 쓴 것만.
- 주소 뒤에 `#failures`, `#predictions`, `#about`을 붙이면 그 화면으로 바로 열립니다. 면접이나 소개 때 실패 사례 링크만 따로 보내기 좋아요.
- "AI가 내 기준을 얼마나 따라오나"는 판단이 20건 쌓이기 전에는 숫자를 보여주지 않습니다.

## 블라인드 비교와 관점 통계

AI 판단을 먼저 보면 사람은 무의식적으로 거기에 끌려가고(앵커링), 그 코멘트가 다음 날 AI 예시로 들어가면 AI가 자기 생각을 다시 배우는 루프가 됩니다. 그래서 순서를 고정했습니다: **내가 먼저 판단 → 저장 → AI 판단 공개.**

**렌즈 7개** (`pipeline.py`의 `LENS_DEFS`와 `admin.html`의 `LENS_DEFS`가 이름·정의까지 같아야 합니다)

사람은 검수 화면의 "렌즈 정의 보기"에서, AI는 프롬프트에서 **같은 정의**를 보고 고릅니다. 이름만 주면 각자 다르게 해석해서 같은 생각을 하고도 태그가 엇갈리고, 그게 일치율 노이즈가 됩니다.

| 렌즈 | 정의 |
|---|---|
| 부품 수급 | 부품을 제때 구하나 — 리드타임, 단종(EOL), 품귀, 특정 공급사 의존, 대체품 유무 |
| 외주 조립·납기 | 외주 공장(EMS·ODM)이 자삽·수삽으로 제때 만들어 내나 — 생산 이관, 업체 생산 능력, 납기 지연 |
| 불량·수율 | 만든 것 중 얼마나 제대로 나오나 — 초기 불량, 수율, 로스, 리콜·반품 |
| 설계 양산성 | 시제품 설계 그대로 수천 대를 만들 수 있나 — 부품 선택, 조립·검사하기 쉬운 구조, 설계 변경 |
| 양산 단가 | 한 대 만드는 데 얼마 드나 — BOM 원가, 금형·초기 투자, 물량에 따른 단가 |
| 수요·시장성 | 누가 왜 사나 — 실제 문제를 푸나, 값만큼 쓸모 있나, 오버엔지니어링은 아닌가 |
| 인증·규제 | 팔기 전에 통과해야 하나 — KC·전파·안전 인증, 수출 규제, 정부 지원 요건 |

앞의 4개는 운영자가 자재과에서 직접 겪은 일(부품 키팅·수량, 외주 조립업체 납기·불량 대응)에서 나왔고, 뒤의 3개는 사업 판단용입니다.

경계가 가까운 두 쌍은 사람과 AI 모두 같은 기준으로 가릅니다.
- 늦어지는 원인이 **부품이 안 와서**면 `부품 수급`, **공장이 못 만들어서**면 `외주 조립·납기`
- 불량이 **결과로 드러난** 이야기면 `불량·수율`, **원인이 설계**에 있으면 `설계 양산성`

**AI 렌즈는 두 번 뽑습니다**

- **내 기준 학습 AI**: 과거 코멘트(같은 카테고리 우선)를 예시로 보고 고른 렌즈
- **기준선 AI**: 과거 코멘트 없이 고른 렌즈 (대조군)

**일치율** = 내 렌즈와 AI 렌즈의 교집합 ÷ 합집합 (Jaccard).

**집계 규칙**
- 내가 **"해당 없음"을 고른 기사는 통계에서 뺍니다.** 개인화 AI, 기준선 AI 양쪽 모두에서요. 단순 동정 기사에서 둘 다 빈칸이라 100%로 세면 점수가 부풀기 때문입니다.
- 빼는 기준은 **내 선택 하나뿐**입니다. "둘 다 비었을 때"처럼 AI 답에 따라 빼면, 개인화 AI와 기준선 AI가 서로 다른 기사 묶음으로 평균을 내게 되어 비교가 불공정해집니다.
- **개인화 효과**는 두 AI 값이 모두 있는 같은 기사끼리의 차이 평균입니다. 기준선 호출이 실패한 기사는 그 비교에서만 빠집니다.
- 통계 탭은 저장된 일치율 숫자가 아니라 **원본 렌즈 기록으로 매번 다시 계산**합니다. 나중에 계산 규칙을 바꿔도 과거 데이터 전체에 그대로 적용됩니다.

**관점 통계** 탭에서 볼 수 있는 것

- 최근 30일 일치율과 초기 20건 일치율
- **개인화 효과** = 내 기준 학습 AI 일치율 − 기준선 AI 일치율
- 주별 추이 (최근 12주)
- 내가 자주 보는 렌즈 vs AI가 자주 고르는 렌즈

**해석할 때 주의할 점:** 일치율만 오르면 "AI가 나를 배웠다"와 "내가 매일 공개되는 AI 렌즈를 보면서 AI처럼 생각하게 됐다"가 구분되지 않습니다. 두 번째 경우엔 기준선 일치율도 같이 오릅니다. 그래서 **기준선과의 차이(개인화 효과)가 벌어지는지**를 근거로 삼아야 합니다. 대학원 면접에서 쓸 때도 "일치율이 올랐다"보다 "같은 모델에 내 코멘트를 넣었을 때와 안 넣었을 때 차이가 몇 %p 벌어졌다"가 훨씬 설득력 있는 주장입니다. 

**초기 구간(콜드 스타트):** 코멘트가 15~20건 쌓이기 전에는 개인화 AI도 참고할 예시가 거의 없어서 기준선과 비슷한 점수가 나오는 게 정상입니다. 그 구간의 차이는 우연에 가깝고, 의미 있는 격차는 그 이후부터 봐야 합니다. 통계 탭에도 20건 미만이면 이 안내가 뜹니다.

**과거 코멘트 예시 고르는 방식**

1차 선별 단계에서 기사 카테고리를 먼저 정하고, 구조화 단계에서는 같은 카테고리 코멘트를 최대 5개, 나머지 3개는 다른 카테고리에서 채웁니다. 각 묶음 안에서는 ⭐ → 최신 순. 같은 카테고리 예시는 프롬프트 맨 끝(질문과 가장 가까운 자리)에 둡니다. 다른 카테고리를 일부 남기는 건 한 관점에만 쏠리지 않게 하기 위해서입니다.

## 환각을 막는 장치

| 위험 | 막는 방법 |
|---|---|
| 없는 기업·수치를 사실처럼 | `extracted`의 모든 값은 원문 구절(`evidence`)이 필요하고, `verify()`가 그 구절이 원문에 실제로 있는지 검사. 없으면 제거하고 제거 개수를 화면에 표시 |
| 근거 없는 스펙·ROI | 프롬프트에서 금지. 추정은 `estimated`로 분리하고 근거가 없으면 `판단불가` |
| 없는 지원사업 매칭 | `programs.json`에 있는 id만 허용 |
| AI가 운영자인 척 | 코멘트는 사람만 쓴다. AI는 질문만 던진다 |
| 목록 밖의 렌즈·카테고리 | `clean_lenses()`가 목록에 없는 값을 버리고 최대 3개로 자름. 카테고리도 목록 밖이면 1차 선별 값으로 대체 |
| AI 판단에 끌려가기 | AI 렌즈와 AI 추정은 저장 후에만 공개, 저장 후 수정 불가 |

## 공개 전에 알아둘 것

- **저작권**: 파이프라인은 RSS 요약만 저장하고, 요약은 AI가 자기 말로 다시 씁니다. 공개 페이지에도 원문 문장을 그대로 붙이지 말고 링크로 연결하세요.
- **공개 저장소에서는** `comments.json`(코멘트·예측·렌즈 기록)과 `admin.html` 파일도 공개됩니다. 코멘트는 원래 공개할 내용이고, 검수 화면은 토큰 없이는 아무것도 저장할 수 없으니 괜찮습니다.
- **개인 투자 기능은 여기에 넣지 마세요.** 매수 추천·종목 시그널은 지금처럼 개인 테크 시그널 사이트(나만 보는 곳)에 두세요.
- **투자 관련 내용**을 유료로 제공하려면 유사투자자문업 신고 대상인지 먼저 확인하세요.
- `comments.json`이 1MB를 넘으면 GitHub Contents API로 읽기 어려워집니다. 그 전에 연도별로 나누면 됩니다. (하루 3~10건이면 몇 년은 충분)

## 손보기 좋은 곳

- `SOURCES`: 수집 키워드. 니치에 맞게 바꾸세요.
- `LENS_DEFS`: 렌즈를 바꾸면 `pipeline.py`와 `admin.html` 양쪽을 같이 고치세요. 이미 쌓인 데이터와 비교가 끊기니 초반에 확정하는 게 좋습니다.
- `SCORE_PROMPT`의 가점·감점 기준: 운영하면서 내 필터를 글로 옮겨 적는 곳.
- `REQUIRED` (admin.html): 하루 필수 검수 개수.
- `TOP_N` 환경변수: 하루에 구조화할 기사 수 (기본 10).
